5  Where your data lives

MedicineBow has three filesystems: home (50 GB, small), project (5 TB, shared with your group, where datasets and results live), and scratch (5 TB, fast, purged after 90 days of inactivity). None is backed up. Install software into /project/<proj>/software, not home — one conda env can fill your home directory.

5.1 Nothing is backed up

Nothing on MedicineBow is backed up. Not home, not project, not scratch.

There are snapshots (point-in-time copies you can sometimes restore from), but they live on the same storage array as your live data — if the array fails, the snapshots fail with it. Snapshots protect against accidental deletion, not hardware loss. Anything you can’t afford to lose needs a copy elsewhere: your institution’s storage, a cloud bucket, or the separate Alcova service, which does have real nightly backups.

5.2 The three filesystems

Path Quota Snapshots Backups Purged
/home/$USER 50 GB yes NO only when you leave UW
/project/<proj> 5 TB yes NO 6 months after project ends
/gscratch/$USER ($SCRATCH) 5 TB yes NO after 90 days of inactivity
/project/<proj>/software +250 GB on top of project yes NO with the project
/lscratch node-local, varies no NO wiped at the end of every job

Check your usage and limits for home, scratch, and project:

arccquota

5.2.1 /home — small, personal, for config not data

50 GB fills fast once a conda environment eats 15 GB of it. Home is for dotfiles, scripts, and small configs — not datasets and not software installs. When home fills up, things break (jobs fail to write logs, logins misbehave), so watch it with arccquota and du -sh ~/* | sort -h.

5.2.2 /project/<proj> — the shared workhorse

5 TB, shared by everyone on your project (e.g. cowy-firesurro). This is where shared datasets, inputs, and results belong. Agree on a directory convention with your group so you don’t clobber each other. It persists for 6 months after the project ends.

5.2.3 /gscratch/$USER — fast and disposable

Also 5 TB, and the fast filesystem — use it as the working directory for jobs with heavy I/O. Files untouched for 90 days are purged automatically. Never keep the only copy of anything here.

Scratch purge is 90 days, not 45

Legacy Confluence docs say 45 days; the current ARCC wiki says 90. Both pages are live, but 90 is the current policy. Either way, don’t treat scratch as storage.

5.2.4 /lscratch — node-local, gone when the job ends

Each compute node has its own local disk at /lscratch. It’s the fastest storage available to a job (no network in the way), ideal for scratch files a single job reads and rewrites constantly. It’s wiped when your job ends, so copy anything you want to keep back to /project or /gscratch before the job exits.

(There is no /data filesystem, despite what some docs suggest.)

5.3 Install software in project space, not home

Install software into /project/<proj>/software, not /home

Your project has an extra 250 GB quota at /project/<proj>/software for installing software. A single conda environment with a few scientific packages can be 10–20 GB — two of those fills a 50 GB home directory.

Point conda, pip, R libraries, and manual builds at project software space from the start. The conda chapter (Chapter 8) shows how.

5.4 A sane layout to adopt on day one

/home/<you>/                      # dotfiles, small scripts, SSH keys
/project/cowy-firesurro/
    software/                     # conda envs, container images, manual builds
    data/                         # shared input datasets
    <you>/                        # your working area within the project
/gscratch/<you>/                  # active job working dirs, heavy I/O, big temp output
