1  Getting started on the cluster

Getting from zero to a shell prompt: what the machine is, how to get an account, and how to log in.

1.1 What a cluster is

1.1.1 Mental model

MedicineBow is not one big computer. It is a few hundred ordinary Linux servers (“nodes”) wired together, all mounting the same shared filesystems, all managed by a program that decides whose job runs where and when. That program is the scheduler (here, Slurm). Learning the cluster is mostly learning to work with the scheduler.

1.1.2 Login nodes vs. compute nodes

There are two kinds of machines, and confusing them is the most common beginner mistake.

Login nodes (mblog1, mblog2) are the front door. When you ssh in or open a terminal in the web portal, you land here. They are shared by everyone at once — dozens of people editing files, submitting jobs, and moving data. Use them for lightweight work: editing scripts, managing files, compiling small things, submitting and checking jobs.

Compute nodes are where computation happens. You never SSH to them directly; you ask the scheduler for one (or many), and it gives you exclusive, dedicated access for a bounded time. The default mb nodes have 96 CPU cores and ~1 TB of RAM each, and the GPU nodes carry up to 8 NVIDIA H100s.

Don’t compute on login nodes

A heavy job on mblog1/mblog2 — a big simulation, a data-crunching Python script, a multi-hour build — slows the machine for everyone logging in. ARCC monitors this and kills runaway login-node processes (and emails you).

Rule of thumb: anything that takes more than a couple of minutes, or uses more than a core or two, belongs in a Slurm job or an interactive session. See Section 5.1.

1.1.3 Why share a machine at all?

If everyone had their own dedicated server, most servers would sit idle while a few people occasionally needed far more than one server could give. Pooling the hardware and scheduling access means:

  • When you need 50 nodes for an ensemble, you can have them (briefly).
  • When you need nothing, someone else uses the hardware you’re not using.
  • A fair-share accounting system stops any one person from hogging everything.

In exchange, you sometimes wait in line and you have to describe your work up front (how many cores, how much memory, how long). Most of this book is about making those two things painless.

1.1.4 What MedicineBow is, concretely

MedicineBow is a RHEL 9 Linux cluster. Its hardware is a mix of:

  • General CPU nodes (the mb partition): 25 nodes, 96 cores and ~1 TB RAM each.
  • GPU nodes: H100, L40S, A30, A6000, and R6000 flavors — for ML, PINNs, and anything CUDA.
  • Absorbed older clusters: the retired Teton, Beartooth, and WildIris clusters now live on as large partitions inside MedicineBow. Teton alone is ~250 nodes.
  • Investor (“condo”) nodes: hardware bought by specific research groups, which others can borrow when it’s idle — but the owner can reclaim it and bump your job (see Section 8.1).

Section 6.1 covers which hardware to ask for, and Section 6.2 covers which choices leave you waiting versus running now.

1.2 Getting an account

1.2.1 How to request an account

Access to MedicineBow for ASCEND/ARID performers is coordinated through the program. To request an account, email Virginia Iglesias (virginia@innosphere.org) and mention that you’re an ASCEND/ARID performer who needs MedicineBow access. She’ll arrange for you to be added to the project.

Accounts are tied to a project — your ASCEND/ARID project — which is also the name you type into every job you run (Section 5.2). Confirm your exact project name with Virginia or your team; this book writes it as <project> in examples, and you substitute your own.

1.2.2 UW accounts vs. ARCC-Only accounts

ASCEND spans UW, CSU, CU Boulder, Mines, NCAR, and NEON, so this distinction affects collaborators:

Full UW account ARCC-Only account
Who UW-affiliated people External collaborators without a UW identity
HPC (MedicineBow) ✅ ✅
GitLab ✅ ✅
Globus data transfer ✅ ❌ cannot use Globus
Other UW services ✅ ❌
ARCC-Only accounts and Globus

External collaborators on ARCC-Only accounts cannot use Globus, the recommended way to move large datasets (Section 3.2). They’ll need a guest collection set up for them, or a UW person to broker transfers. Plan for this early if your data lives at CSU or NCAR.

1.2.3 The free tier

Each researcher’s baseline allocation:

  • 100,000 CPU core-hours per year
  • 20,000 GPU-hours per year

That is plenty for getting started — 100,000 core-hours is roughly one 96-core node running flat out for six weeks. Larger allocations and investor projects exist beyond this. Core-hours are counted as (cores × wall-clock hours), a reason not to over-ask for resources (Section 5.3).

1.2.4 The practical checklist

  1. Email Virginia Iglesias (virginia@innosphere.org) to request a MedicineBow account, mentioning that you’re an ASCEND/ARID performer.
  2. You’ll be added to the project and issued a UW username. Then log in for the first time — see Section 1.3.
  3. If you’re an external (non-UW) collaborator, say so — you’ll get an ARCC-Only account, which can’t use Globus (Section 3.2), so ask how you’ll move data.

No VPN is required to reach ARCC, on campus or off, so once your account exists you can log in from anywhere.

1.3 First login, the portal, and SSH keys

1.3.1 Two ways in: portal and SSH

MedicineBow has a single hostname that serves both the web portal and SSH: medicinebow.arcc.uwyo.edu.

  • The web portal (Open OnDemand) is a browser interface: a file explorer, a terminal, job submission forms, and interactive apps (desktop sessions, RStudio, Jupyter). Start here on day one.
  • SSH is the terminal way in, and how you’ll work day-to-day once set up. It requires a key you generate through the portal first.
Don’t use “Southpass”

Older notes may point you at southpass.arcc.uwyo.edu, the portal for the retired Beartooth cluster. The DNS name still resolves but has no live service behind it. The current portal is medicinebow.arcc.uwyo.edu.

1.3.2 Step 1 — Log into the portal

Go to https://medicinebow.arcc.uwyo.edu and sign in with your UW username and password. You’ll be prompted for Duo two-factor authentication. If you’ve never set up Duo, do it at https://wyosecure.uwyo.edu. No VPN is needed.

Once in, note the Files menu (browse /home, /project, /gscratch), the Clusters → Shell option (a terminal in your browser), and the Interactive Apps menu.

1.3.3 Step 2 — Generate your SSH key with the SSH Key Manager

SSH on MedicineBow is key-and-certificate based, not password based. Generate a key pair through the portal:

  1. In the portal, open the SSH Key Manager.
  2. Generate a key. It downloads as a zip named after your username.
  3. Unpack it into your local ~/.ssh and fix permissions:
unzip ~/Downloads/<username>.zip -d ~/.ssh
chmod 700 ~/.ssh && chmod 600 ~/.ssh/*
ssh-add

Now you can connect from your own terminal:

ssh <username>@medicinebow.arcc.uwyo.edu
SSH keys expire after one year

Roughly a year after setup, your ssh stops working — permission denied, no obvious reason. The key expired. Go back to the portal’s SSH Key Manager, generate a fresh key, and unzip it into ~/.ssh again. This is by design.

1.3.4 Step 3 — A comfortable SSH config (optional)

Add this to ~/.ssh/config on your laptop so you can just type ssh medbow:

Host medbow
    HostName medicinebow.arcc.uwyo.edu
    User <username>
    ServerAliveInterval 60
    ServerAliveCountMax 5

ServerAliveInterval sends a small keepalive every 60 seconds so campus or home firewalls don’t silently drop your connection while you’re reading output.

1.3.5 Which door should I use?

You want to… Use
First-time setup, generate SSH keys Portal (required)
A quick browser terminal from any machine Portal → Clusters → Shell
A graphical desktop, RStudio, Jupyter Portal → Interactive Apps
Everyday scripting, editing, job submission SSH from your terminal
Drag-and-drop a few files Portal → Files (for big data, see Section 3.2)

Once you can log in and get a shell prompt, continue to the Linux survival kit (Chapter 2), or skip ahead to storage (Section 3.1) and Slurm (Section 5.1) if you already know a terminal.
